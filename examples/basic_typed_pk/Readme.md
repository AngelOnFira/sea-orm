# SeaORM typed-PK example

Discord-shaped chat data model that exercises the per-entity
`sea_orm::Id<E, T>` primary key wrappers produced by
`sea-orm-cli generate entity --with-pk-newtypes`.

Patterns covered:

- **Cross-entity ID safety.** Every snowflake `i64` PK gets a distinct
  alias (`UserId`, `GuildId`, `ChannelId`, `MessageId`) so passing the
  wrong id to the wrong API is a compile error.
- **Multiple FKs to the same parent.** `message` has both `author_id`
  and `mention_user_id` referencing `user`. Both columns share the
  parent's `UserId` type (codegen doesn't role-wrap non-PK FK columns).
- **Self-reference.** `message.reply_to_message_id: Option<MessageId>`
  resolves to the local alias, not `super::message::MessageId`.
- **Composite primary keys with typed components.** `member` is keyed
  by `(GuildId, UserId)`; `reaction` by `(MessageId, UserId, String)`.
- **Role wrappers on a junction.** `user_follower` has two PK columns
  both FK-referencing `user.id` — codegen emits
  `UserFollowerPkUserId` and `UserFollowerPkFollowerId` so a positional
  swap fails to compile.

## Running

```sh
cargo run
```

The example uses in-memory SQLite, creates the schema from the
generated entities via `Schema::create_table_from_entity`, and walks
through realistic operations (`send_message`, `add_member`,
`ban_user_from_guild`, etc.) defined in `src/operations.rs`. Each
operation takes typed PKs in its signature.

## Regenerating the entities

Everything under `src/entity/` is produced from `chat.sql` by
`sea-orm-cli`. To regenerate:

```sh
sqlite3 /tmp/typed_pk_chat.db < examples/basic_typed_pk/chat.sql
cargo install --path sea-orm-cli --debug
sea-orm-cli generate entity \
    --database-url sqlite:///tmp/typed_pk_chat.db \
    --with-pk-newtypes \
    --output-dir examples/basic_typed_pk/src/entity
```

The committed entity files are a snapshot — like `examples/basic`,
they're regenerated by hand when the schema changes rather than at
build time.
